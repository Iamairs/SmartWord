# 商务报告润色

## 工作流

1. 先判断文档受众：内部汇报、客户材料、管理层摘要或项目复盘。
2. 读取相关段落后识别主要问题：口语化、重复、结论不前置、缺少下一步、风险表达不清。
3. 优先保持事实不变，只调整结构、语气和表达密度。
4. 对长段落可改为“背景、进展、问题、建议、下一步”的条目结构。
5. 需要全文批量改写时，先分区规划并请求用户确认。

## 输出要求

- 先说明整体修改策略。
- 展示关键段落的改写前后差异。
- 不编造数据、结果、客户反馈或承诺。

## 安全边界

- 不执行 Skill 脚本。
- 不修改事实、金额、日期、主体名称，除非用户明确要求并确认。
