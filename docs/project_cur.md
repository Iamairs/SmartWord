# 当前需求说明：Agent 回滚策略重构为步骤级提交

## 1. 背景

当前 Agent 模式的文档写入仍采用“任务级 UndoRecord”思路：

- 第一次真实写入开始时创建整次任务级 `UndoScope`
- 之后所有写步骤共用这一条 Undo 链
- 只有整次运行最终成功才提交
- 如果中途异常、取消、连续失败达到上限或待修复终止，则在 `finally` 里整体回滚

这个设计虽然能保护文档不留下半成品，但会带来明显业务问题：

1. 前面已经验证成功的改动，会因为后面某一步失败被整轮抹掉。
2. 文档被整轮回滚后，Todo Board 仍可能保留旧进度，导致用户看到“文档已回去，但任务板还显示已完成”。
3. 用户感知上更像“系统全白干”，不符合 Word 编辑场景下“前面改对的应该保住，当前失败的只撤当前步”的直觉。

## 2. 当前需求

本轮需要把 Agent 回滚策略重构为：

- 步骤级提交
- 当前步回滚
- 暂停决策

具体要求：

1. 每一个真实文档写步骤都独立开启 UndoScope。
2. 写后验证通过后，立即提交当前步骤，不再受后续失败连坐。
3. 当前步骤执行失败或验证失败时，只回滚当前步骤，不回滚之前已提交的步骤。
4. 当前步骤连续失败达到上限后，任务进入暂停，由用户决定继续、重建或放弃。
5. Todo Board 必须和“当前步回滚”联动，不能再出现文档已回退但 Todo 仍保留旧进度的情况。

## 3. 已确认的关键决策

### 3.1 回滚粒度

- 保留回滚能力，但回滚粒度从“整次任务”收缩为“当前失败步骤”
- 已验证成功的步骤视为可信成果，默认不自动撤销

### 3.2 任务收尾

- 当前写步骤失败 3 次：暂停任务，而不是整轮回滚
- 当前写步骤回滚成功：进入 `Paused`
- 当前写步骤结果不可信：进入 `RecoveryRequired`

### 3.3 Todo Board 语义

- “恢复旧任务板”不再表示直接沿用失败前旧板
- 需要恢复到“当前写步骤开始前”的可信任务板快照
- 当前写步骤期间若发生 `todo_write` 推进当前任务，回滚时也要一起退回

## 4. 设计约束

- 后端仍为 .NET Framework 4.7.2
- 注释与新增文档保持 UTF-8 和中文说明
- 本轮不做 Word 文档内容级 diff 比对
- 本轮优先在现有 `AgentOrchestrator + TodoManager + UndoRecordWrapper` 结构上渐进式改造，不推倒重写

## 5. 本轮交付目标

1. 将 `IUndoScopeFactory / WordApplicationWrapper / UndoRecordWrapper` 改成步骤级 Undo 接口语义。
2. 在 `AgentOrchestrator` 中引入当前写步骤事务状态，并移除“整轮 finally 回滚”默认路径。
3. 在 `TodoManager` 中增加当前写步骤快照与回滚恢复能力。
4. 收紧 `todo_write`，禁止在当前写步骤未提交前推进当前任务状态。
5. 更新前端暂停 / 恢复展示逻辑，准确表达“当前步已回退、之前成果已保留”。
6. 补齐自动化测试并完成 git 提交。
