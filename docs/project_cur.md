# 当前需求：上下文压缩策略重构

## 需求背景

SmartWord 当前上下文压缩基于固定阈值与规则摘要，不能很好适配用户可配置的模型上下文长度，也缺少轻裁剪、LLM 滚动摘要和程序硬状态分层。需要按已确认方案实现一套更贴合 Word Agent 运行场景的压缩流程。

## 用户确认的关键要求

- 模型上下文长度由用户设置，默认 256K，触发阈值按比例计算，不使用固定 token 数。
- Stage 1 是轻量工具结果裁剪，不设置单条最多裁剪 30%-50% 或本轮最多释放 15%-20% 这类硬比例。
- 始终保留第一条 `user` 消息，因为它可能是 Skill 使用提示等系统注入上下文。
- 不引入 Compaction Debt。
- 不增加压缩期间文档状态变化检查。
- 写入状态按当前代码实现描述为“待修复/已回滚/已验证提交”，不使用“未验证写入”作为长期状态。

## 实现注意事项

- 复杂功能需新增测试并更新 `docs/已实现的功能.md`。
- 保持 OpenAI-compatible tool call 链协议安全，不能留下孤立 tool 消息或未闭合 tool call。
- 旧 `ConversationCompressor` 保留为 fallback，避免 LLM compaction 失败时直接中断。
