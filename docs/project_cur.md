# 当前需求说明：Todo Board 回滚显示与真实执行状态彻底对齐

## 1. 背景

当前 Agent 模式已经完成“步骤级提交 + 当前步回滚 + 暂停决策”的主体改造，但在 `verify_script` 失败后的链路上仍有一个关键体验问题：

- 文档层面并不会把整个任务从头重做，只会继续修当前失败步骤
- 但前端 Todo Board 会短暂显示为“之前完成的步骤又变回未完成”
- 后续当模型再次执行 `todo_write` 后，前端显示又恢复正常

这说明当前系统里的三个语义还没有完全对齐：

1. **可信已提交进度**：真正已经确认保留的 Todo 进度
2. **当前写步骤运行态**：当前步骤的验证、修复、回退过程
3. **前端展示事件语义**：前端收到的是普通同步、回滚恢复，还是暂停快照

## 2. 当前问题本质

这不是单纯的前端渲染 bug，而是状态模型仍然存在“可信状态”和“运行态快照”混用的问题：

- `TodoBoard.Items` 同时承担“稳定展示板”和“恢复锚点”两种职责
- 回滚时依赖的快照与正常同步时使用的是同一份完整板对象
- 前端收到 `todo_board_updated` 后会整板覆盖，但事件里没有明确区分“普通同步”还是“回滚恢复”

结果就是：

- 实际执行继续沿用 `pendingWriteStep` 修当前步骤
- 但前端会把一份旧快照误当成新的正常进度

## 3. 本轮修复目标

本轮要做的是“完备彻底的修复”，不是只在前端加一个补丁。具体目标：

1. 在后端显式维护“最近可信提交的 Todo Board 快照”，不再只依赖当前运行态板子。
2. 当前写步骤开始、提交、回滚、暂停、恢复时，都优先围绕“可信快照”运转。
3. `todo_board_updated` 事件补充更新类型，让前端区分：
   - 普通同步
   - Todo 写入更新
   - 回滚恢复到可信检查点
4. 前端 Todo Board 面板增加明确提示，不再把回滚恢复态伪装成普通进度刷新。
5. 对恢复旧板、暂停继续、异常恢复、预算暂停等链路统一语义，避免再次出现“显示倒退但执行没倒退”。

## 4. 设计约束

- 继续沿用现有 `TodoManager + AgentOrchestrator + WebViewBridge + Vue Store` 架构渐进改造
- 保持 .NET Framework 4.7.2 兼容
- 新增注释与文档使用 UTF-8 中文
- 不引入任务级整轮回滚，不破坏现有“步骤级提交 + 当前步回滚”原则
- 兼容旧版 Todo JSON，缺少新增字段时可自动补默认值

## 5. 本轮交付

1. 扩展 `TodoBoard` 持久化字段，引入最近可信提交快照。
2. 重构 `TodoManager` 的快照生成、恢复和回滚逻辑，优先从可信快照恢复。
3. 扩展 `AgentEvent / WebViewBridge`，给 Todo 事件补充更新语义。
4. 改造前端 `chat` store 与 `TodoBoardPanel`，正确呈现回滚恢复和普通更新。
5. 补齐自动化测试、更新文档，并提交 git。
