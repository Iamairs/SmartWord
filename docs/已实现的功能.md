## 3. 已实现的功能

### 3.1 Word 宿主集成与插件入口

#### 3.1.1 VSTO 插件启动骨架

- 已完成 `ThisAddIn` 启动与关闭生命周期接入，支持插件初始化、日志初始化、依赖注入容器装配与资源释放。
- 已完成自定义任务窗格（Task Pane）创建，侧边栏可在 Word 内部稳定挂载并保持窄栏布局。
- 已接入 `Serilog` 文件日志，覆盖插件启动、前端加载、请求处理、LLM 调用等关键路径，便于定位运行时问题。

#### 3.1.2 Ribbon 功能区入口

- 已提供 `SmartWord` 功能区入口按钮，用于显示或隐藏侧边栏。
- 已实现 Ribbon 状态与 Task Pane 可见性联动，避免界面状态不同步。
- 已收敛为单一 Ribbon 机制，减少宿主层重复实现带来的维护成本。

#### 3.1.3 WebView2 宿主承载

- 已完成 WebView2 宿主集成，可在 Word 侧边栏中加载前端页面。
- 已通过宿主对象（HostObject）建立 WebView2 与 C# 间的双向调用通道。
- 已支持前端资源映射与基础页面加载诊断日志，便于排查空白页、加载失败等问题。

### 3.2 前端侧边栏与基础交互

#### 3.2.1 聊天式侧边栏界面

- 已实现基于 Vue 3 的聊天主界面，包含头部区域、消息列表、输入框、发送按钮与设置入口。
- 已支持用户消息与助手消息分开展示，并适配 Word 插件侧边栏的窄宽度使用场景。
- 已支持基础 Markdown 渲染，便于展示结构化回答内容。

#### 3.2.2 流式输出与交互状态

- 已支持后端流式文本分片逐段渲染，用户可以实时看到模型输出过程。
- 已提供请求处理中状态与打字指示效果，降低长请求的等待割裂感。
- 已支持在前端显式切换 `对话交流 / 规划任务 / 自主执行` 三种模式，并同步展示当前选择模式。

#### 3.2.3 设置面板与宿主桥接

- 已在前端提供设置面板，可编辑默认/轻量/重量模型的 Base URL、API Key 与模型名。
- 已支持“写操作前确认”与“自定义系统指令”等选项的前端配置与保存。
- 已封装 `hostBridge`，统一处理 `GetSettingsJson`、`SaveSettingsJson`、`SendMessageAsync`、`NavigateToParagraph` 等宿主调用，并强制请求显式携带 `manualMode`。
- 已提供浏览器预览降级模式，在非 WebView2 环境下可使用本地模拟请求与 `localStorage` 存储设置。

#### 3.2.4 工具链路可视化与引用跳转

- 已新增 `ThoughtActionTrace` 组件，用于展示工具调用的开始、完成、失败/拒绝等过程信息。
- 已支持助手回答中的 `[n]` 溯源标记渲染为可点击按钮。
- 已支持点击引用后通过宿主桥接跳转到 Word 对应段落。
- 已新增 `ContentPreviewPanel`，用于在 Agent 模式写入前展示待确认操作。
- 已新增 `ChangesSummaryPanel`，用于在任务完成后汇总本次改动并提供段落跳转入口。
- 当前引用跳转粒度为段落级，字符级高亮尚未实现。

### 3.3 Ask 模式与只读工具链

#### 3.3.1 Ask 模式主流程

- 已打通 Ask 模式完整闭环：前端手动选择模式并发起请求 -> 文档上下文注入 -> LLM 工具调用 -> 流式回答 -> 前端展示。
- Ask 模式下仅注册只读工具，不允许写入类工具进入执行链路。
- 已支持 Ask 模式回答中的引用编号与前端溯源联动。

#### 3.3.2 文档上下文水合

- 已实现基于 `ReadOnlyDocumentSnapshotBuilder` 的文档只读快照构建，可统一获取当前活动文档的名称、路径、段落数、字数、页码、复杂度、标题大纲、光标位置、选区信息、表格数、图片数、批注数与文档状态。
- 已将上述上下文注入系统提示词，供 Ask 模式回答与工具选择使用。
- 已具备文档切换检测基础，防止多轮交互中跨文档串话。

#### 3.3.3 只读工具体系

- 已重构 `probe_document`：用于获取文档整体信息、状态、统计数据、最近标题、光标信息和选区信息，并补充批注数量等结构统计。
- 已重构 `read_section`：支持按标题、按段落范围、按光标附近读取段落内容，并在标题模糊匹配、范围裁剪、结果截断时返回 `diagnostics`。
- 已重构 `grep_document`：支持关键字或标准 .NET 正则搜索、章节/段落/选区附近范围限定、同段多命中偏移返回、真实总命中统计与非法正则显式报错。
- 已重构 `get_selection_context`：支持无显式选区时回退到光标所在段落，并对跨段选区给出诊断提示。
- 已新增 `read_table`：支持按 0 基索引读取表格结构、锚点段落与单元格内容。
- 已新增 `read_annotations`：支持读取批注作者、时间、内容、锚点文本与所在段落。
- 已新增 `ReadScopeResolver`、`ParagraphSearchEngine`、`ParagraphRangeLocator` 等公共只读组件，统一范围解析、搜索与光标段落定位逻辑。
- 所有 Word COM 调用已通过 `WordApplicationWrapper.InvokeAsync` 回到宿主线程执行，减少跨线程访问风险；关键读取路径已补充宿主侧诊断日志。

#### 3.3.4 工具注册、权限与保护

- 已实现 `ToolRegistry`，支持按模式过滤工具定义。
- 已实现 `PermissionGuard`，可阻止 Ask 模式下的写入类工具调用。
- 已在编排层加入最大迭代次数、单轮最大工具调用数、工具执行超时与错误消息截断等保护措施。

#### 3.3.5 Agent 模式写入闭环（Phase 3）

- 已新增 `verify_change`，支持 `text_contains`、`text_equals`、`text_not_contains`、`style_equals`、`paragraph_exists` 等结构化校验。
- 已新增 `patch_range` MVP，支持 `replace_text`、`insert_paragraph_after`、`set_paragraph_style`、`delete_paragraph` 四类安全写入操作。
- 已新增 `execute_script` 与 Roslyn 脚本执行器，作为复杂编辑场景的受控后备路径，并接入静态安全校验。
- 已在 `AgentOrchestrator` 中接入文档可写性前置检查、写前确认等待、连续失败熔断、任务级 Undo 接入与 `change_applied` 事件透出。
- 已通过 `IConfirmationChannel + WebViewConfirmationChannel + SmartWordBridge` 打通真实的宿主确认回传链路，避免双 bridge 实例问题。
- 已将 Undo 回滚语义修正为“同文档尽量自动回滚，文档切换时仅做最佳努力并明确提示”。

### 3.4 LLM 接入、工具调用与模型能力分流

#### 3.4.1 OpenAI Compatible 基础接入

- 已实现 `OpenAiCompatibleClient`，支持兼容 OpenAI Chat Completions 协议的服务端接入。
- 已支持 SSE 流式读取与分片转发，可将模型输出实时推送到前端。
- 已支持工具调用请求体构造、`delta.tool_calls` 累积解析以及最终 `assistant` 消息拼装。

#### 3.4.2 多轮工具调用编排

- 已在 `AgentOrchestrator` 中实现多轮“模型回答 -> 工具调用 -> 工具结果回填 -> 再次请求模型”的基础循环。
- 已支持工具调用事件输出，包括开始、完成、拒绝、上下文压缩提示、任务完成等事件。
- 已支持将工具结果写入对话历史，形成后续推理可继续消费的消息序列。

#### 3.4.3 引用映射与溯源数据

- 已新增 `CitationEntry` 领域模型，用于维护 `[n]` 到文档段落的稳定映射。
- 已在工具输出中附加 `citation_entries` 信息，用于前端点击跳转与最终回答中的可见引用。
- 已支持从助手最终回答中抽取实际使用过的引用编号并返回给前端。

#### 3.4.4 模型能力分流

- 已实现基于模型能力的自动分流，不再单纯依赖人工切换模型。
- 已支持判断模型是否支持工具调用，以及是否要求回放 `reasoning_content`。
- 当前已内置的能力规则包括：
  - `DeepSeek-V3.2`、`GLM-4.7`：支持工具调用，并要求在工具链路中回放 `reasoning_content`
  - `*Speciale*`：按不支持工具调用处理
  - 其他模型：默认按支持标准工具调用处理
- 当当前模式要求工具调用但首选模型不支持时，系统会自动尝试切换到备选模型。
- 当首选与备选模型都不支持工具调用时，系统会自动降级为纯文本回答模式，并在提示词中明确要求模型说明“无法读取当前 Word 文档内容”。

#### 3.4.5 API 调用诊断日志

- 已在 LLM 请求前记录接口地址、模型名、工具数、消息摘要与完整请求体。
- 已在接口响应后记录状态码、响应头、响应体与 SiliconFlow `TraceId` 等关键信息。
- 已将工具链路中的兼容性问题诊断能力提升到“可直接对照请求体排查”的级别，便于定位 `messages illegal`、工具调用协议不兼容等问题。

### 3.5 对话存储、配置管理与长期持久化

#### 3.5.1 对话存储

- 已实现 `InMemoryConversationStore`，支持按文档路径隔离对话历史。
- 已支持用户消息、助手消息、工具结果消息的写入与读取。
- 已支持基础 token 数量估算，用于上下文过大时触发保护逻辑。
- 已保留 `SqliteConversationStore` 骨架，但工具结果持久化尚未完全落地。

#### 3.5.2 应用级设置读写

- 已支持从 `%AppData%\\SmartWord\\settings.json` 读取长期配置。
- 已支持默认、轻量、重量模型各自的 Base URL / API Key / Model 配置。
- 已支持环境变量覆盖配置项，便于调试与部署。

#### 3.5.3 设置即时生效

- 已支持前端保存设置后由宿主立即写回本地配置文件。
- 已支持保存后同步刷新当前进程中的 `LlmClientOptions` 与 `SmartWordSettings` 单例。
- 新发起的请求无需重启 Word 即可使用最新模型与接口配置。

### 3.6 测试、验证与当前边界

#### 3.6.1 自动化测试

- 已建立 `tests/SmartWord.Application.Tests` 测试项目。
- 已覆盖 `ToolRegistry`、`PermissionGuard`、`OpenAiCompatibleClient` 消息序列化、模型能力分流等关键逻辑的单元测试。
- 已补充只读工具重构相关的纯逻辑测试，覆盖段落定位、读取范围解析、搜索多命中/非法正则、工具 schema 契约等关键路径。
- 已补充 Phase 3 相关测试，覆盖 `AgentOrchestrator` 的文档不可写拦截、确认跳过、连续失败熔断、写入成功事件透出，以及 `PatchRangeRequest`、`VerifyChangeEvaluator`、`ScriptSecurityValidator` 等纯逻辑能力。
- 当前自动化测试重点覆盖应用层、基础设施层与 OfficeIntegration 中可提纯的只读逻辑，尚未建立完整的 Word 宿主集成测试体系。

- 已验证以下项目可在当前环境正常构建：
  - `SmartWord.Core`
  - `SmartWord.OfficeIntegration`
  - `SmartWord.Infrastructure`
  - `SmartWord.Application`
- 已验证 `tests/SmartWord.Application.Tests` 可正常执行并通过。
- 已验证前端 `web/SmartWord.WebClient` 可正常构建。

#### 3.6.3 当前阶段边界

- 当前已完成 Ask 模式只读链路与 Agent 模式最小写入闭环，`patch_range -> verify_change` 与脚本后备路径均已落地。
- Plan 模式采访流程、Plan -> Agent 上下文重构与 SQLite 持久化仍未完成，依旧属于后续阶段任务。
- 当前自动化测试与前端构建已验证通过，但本机环境仍缺少 VSTO/Word 宿主构建与手工 E2E 条件，因此 AddIn 真宿主验证需在具备 Office 环境的机器上补做。
