## 3. 已实现的功能

### 3.1 Word 宿主集成与插件入口

#### 3.1.1 VSTO 插件启动骨架

- 已完成 `ThisAddIn` 启动与关闭生命周期接入，支持插件初始化、日志初始化、依赖注入容器装配与资源释放。
- 已完成自定义任务窗格（Task Pane）创建，侧边栏可在 Word 内部稳定挂载并保持窄栏布局。
- 已接入 `Serilog` 文件日志，覆盖插件启动、前端加载、请求处理、LLM 调用等关键路径，便于定位运行时问题。

#### 3.1.2 Ribbon 功能区入口

- 已提供 `SmartWord` 功能区入口按钮，用于显示或隐藏侧边栏。
- 已实现 Ribbon 状态与 Task Pane 可见性联动，避免界面状态不同步。
- 已收敛为单一 Ribbon 机制，减少宿主层重复实现带来的维护成本。

#### 3.1.3 WebView2 宿主承载

- 已完成 WebView2 宿主集成，可在 Word 侧边栏中加载前端页面。
- 已通过宿主对象（HostObject）建立 WebView2 与 C# 间的双向调用通道。
- 已支持前端资源映射与基础页面加载诊断日志，便于排查空白页、加载失败等问题。
- 已补充关闭阶段事件回推保护与确认等待注册释放，降低侧边栏销毁或宿主结束时的对象释放异常风险。

### 3.2 前端侧边栏与基础交互

#### 3.2.1 聊天式侧边栏界面

- 已实现基于 Vue 3 的聊天主界面，包含头部区域、消息列表、输入框、发送按钮与设置入口。
- 已支持用户消息与助手消息分开展示，并适配 Word 插件侧边栏的窄宽度使用场景。
- 已支持基础 Markdown 渲染，便于展示结构化回答内容。
- 已完成面向 280-360px Word 侧边栏的新一轮视觉优化：顶部操作区、消息卡片、输入区、快捷任务、设置、工具轨迹与写入确认面板采用统一的主题 token、表面层级、状态色和焦点反馈。
- 已将主窗口调整为固定视口布局，消息区独立滚动、输入区稳定停靠底部，避免窄栏下页面整体跳动或输入区被挤出视口。
- 已采用手机 AI 聊天式页面骨架：顶部收敛为单行应用栏，左上角菜单打开覆盖式导航抽屉，聊天页只承载消息和任务执行状态。
- 已将常用任务、任务历史、Skill 与设置拆分为独立功能页；非聊天页隐藏底部输入区并使用完整主内容高度，避免多个面板与消息区争抢空间。
- 已将助手回答改为轻量无边框内容流，用户消息改为靠右气泡，并缩减消息外围留白，提升窄栏下的可读内容密度。

#### 3.2.2 流式输出与交互状态

- 已支持后端流式文本分片逐段渲染，用户可以实时看到模型输出过程。
- 已提供请求处理中状态与打字指示效果，降低长请求的等待割裂感。
- 已支持在前端显式切换 `对话交流 / 规划任务 / 自主执行` 三种模式，并同步展示当前选择模式。
- 已将高频流式 chunk 按动画帧合并后再写入响应式状态，降低 WebView2 在长回答期间的更新频率。
- 已增加 Markdown 渲染缓存，历史消息内容未变化时不再重复解析；引用列表变化时会自动失效对应缓存，保证引用按钮正确刷新。
- 已优化自动滚动策略：只有用户仍在消息底部附近时才跟随流式回答，用户回看历史消息时不会被强制拉回；滚动更新在 DOM 稳定后直接完成，避免后台标签页暂停动画帧后无法跟随。
- 已支持 `prefers-reduced-motion`，减少不必要动画；消息卡片保持稳定真实高度，避免延迟高度计算破坏自动滚动。

#### 3.2.3 设置面板与宿主桥接

- 已在前端提供设置面板，可编辑默认/轻量/重量模型的 Base URL、API Key 与模型名。
- 已支持四档执行权限与“自定义系统指令”等选项的前端配置与保存；权限档位包括只读模式、写入前确认、自动安全写入、全自动执行。
- 已封装 `hostBridge`，统一处理 `GetSettingsJson`、`SaveSettingsJson`、`SendMessageAsync`、`NavigateToParagraph` 等宿主调用，并强制请求显式携带 `manualMode`。
- 已提供浏览器预览降级模式，在非 WebView2 环境下可使用本地模拟请求与 `localStorage` 存储设置。

#### 3.2.4 工具链路可视化与引用跳转

- 已新增 `ThoughtActionTrace` 组件，用于展示工具调用的开始、完成、失败/拒绝等过程信息；轨迹折叠时显示“处理中/已处理 + 总耗时”，展开后以轻量时间线展示完整调用链路，并在受限高度区域内滚动查看详情。每轮轨迹会绑定到对应的助手消息，执行中和回答完成后均可查看，不再停留在消息列表顶部。

- 已支持点击引用后通过宿主桥接跳转到 Word 对应段落。

- 已新增 `ChangesSummaryPanel`，用于在任务完成后汇总本次写入状态、区分“已执行写入”和“已验证生效”，并提供段落跳转入口。

#### 3.2.5 Agent 阶段 Todo Board 任务板

- 已新增 `TodoBoardPanel`，用于在 Agent 执行阶段展示当前 Todo Board、当前活动任务和整体统计信息。
- 已扩展前端 `chatStore`，可维护 `activeTodoBoard`、`currentTodoId` 与 `todoBoardVisible` 等状态，并按后端完整快照整板刷新。
- 已支持前端接收 `todo_board_ready`、`todo_board_updated`、`todo_reminder_injected` 三类事件，实现任务板实时同步。
- 已进一步给 Todo 前端事件补充“更新语义”区分：普通同步、Todo 写入同步、回滚恢复、提醒注入不再共用一套无差别刷新语义，降低“显示回退但执行未回退”的割裂感。
- 已为 `TodoBoardPanel` 增加回滚恢复提示条与最近可信检查点说明；当当前写步骤验证失败并回退时，前端会明确提示“当前步已回退，任务板已恢复到最近可信检查点”，而不是默默伪装成普通进度刷新。
- 已在 Plan 面板点击“开始执行”时携带结构化 `activePlan` 发往后端，为 Plan -> Agent 初始化 Todo Board 提供稳定输入。
- 已将 Plan 面板点击“开始执行”的 Todo 启动策略调整为“当前计划优先”：只要请求携带 `activePlan` 且没有显式恢复/暂停决策，后端会直接按当前计划重建 Todo Board，不再弹出恢复旧板/重建/丢弃的选择面板。
- 已新增独立的 `TodoBoardRecoveryPanel`，当检测到中断、崩溃样残留或旧版本脏板时，会先阻断 Agent 进入模型并要求用户选择恢复旧板、按当前计划重建或丢弃后新建空板。

- 已支持暂停态 `skip_current_todo` 决策：系统会恢复最近可信任务板快照，将当前失败 Todo 标记为 `Skipped`，自动推进后续待办并继续执行；用户选择停止任务时，会保留已验证文档修改并清理当前文档的暂停 Todo Board。
- 已支持执行中取消：Ask / Plan / Agent 加载态均可取消，写确认面板提供“取消任务”，Plan 采访面板提供“取消规划”；取消后前端会清理确认、问题和 Todo 恢复等待状态。

### 3.3 Ask 模式与只读工具链

#### 3.3.1 Ask 模式主流程

- 已打通 Ask 模式完整闭环：前端手动选择模式并发起请求 -> 文档上下文注入 -> LLM 工具调用 -> 流式回答 -> 前端展示。
- Ask 模式回答依赖当前 Word 文档内容的问题时，会在首轮通过 OpenAI 兼容协议的 `tool_choice=required` 强制产生真实工具调用并刷新证据，不再仅凭持久化历史回答或历史工具结果直接作答；后续轮次恢复 `auto`，因此既能展示真实工具轨迹，也能正常输出最终答案。
- Plan 模式生成依赖当前文档事实的计划时，同样会在首轮强制调用工具确认文档状态，后续轮次恢复自动工具选择；与文档事实无关的纯流程规划仍允许直接生成。
- Ask 模式下仅注册只读工具，不允许写入类工具进入执行链路。
- 已为前端聊天会话生成独立 `conversationId`；新会话不会继续携带同一文档旧会话的消息，Plan -> Agent 也会建立新的对话上下文，同时保留任务历史和 Todo Board 的文档维度。
- 已支持 Ask 模式回答中的引用编号与前端溯源联动。

#### 3.3.2 文档上下文水合

- 已实现基于 `ReadOnlyDocumentSnapshotBuilder` 的文档只读快照构建，可统一获取当前活动文档的名称、路径、段落数、字数、页码、复杂度、标题大纲、光标位置、选区信息、表格数、图片数、批注数与文档状态。
- 已将上述上下文注入系统提示词，供 Ask 模式回答与工具选择使用。
- 已具备文档切换检测基础，防止多轮交互中跨文档串话。

#### 3.3.3 只读工具体系

- 已重构 `probe_document`：用于获取文档整体信息、状态、统计数据、最近标题、光标信息和选区信息，并补充批注数量等结构统计。
- 已重构 `read_section`：支持按标题、按段落范围、按光标附近读取段落内容，并在标题模糊匹配、范围裁剪、结果截断时返回 `diagnostics`。
- 已重构 `grep_document`：支持关键字或标准 .NET 正则搜索、章节/段落/选区附近范围限定、同段多命中偏移返回、真实总命中统计与非法正则显式报错。
- 已重构 `get_selection_context`：支持无显式选区时回退到光标所在段落，并对跨段选区给出诊断提示。
- 已新增 `read_table`：支持按 0 基索引读取表格结构、锚点段落与单元格内容。
- 已新增 `read_annotations`：支持读取批注作者、时间、内容、锚点文本与所在段落。
- 已新增 `ReadScopeResolver`、`ParagraphSearchEngine`、`ParagraphRangeLocator` 等公共只读组件，统一范围解析、搜索与光标段落定位逻辑。
- 已补强只读工具的 schema 与提示词约束，明确 `scope` 必须传真实 JSON 对象、`from_para/to_para` 与各类 `para_index` 一律使用 0-based、`read_table.table_index` 也是 0-based。
- 所有 Word COM 调用已通过 `WordApplicationWrapper.InvokeAsync` 回到宿主线程执行，减少跨线程访问风险；关键读取路径已补充宿主侧诊断日志。
- 已强化 COM 生命周期基础设施：新增本地拥有 RCW 的逆序去重释放作用域、关闭后拒绝调用且可收尾排队任务的 UI 调度器、仅用于幂等只读操作的 Word Busy 有限重试；EvalRunner 自建 Word 路径会按 Content、Document、Documents、Application 顺序清理，且不会影响 VSTO 宿主 Word。

#### 3.3.4 工具注册、权限与保护

- 已实现 `ToolRegistry`，支持按模式过滤工具定义。
- 已实现 `PermissionGuard`，可阻止 Ask 模式下的写入类工具调用。
- 已在编排层加入最大迭代次数、单轮最大工具调用数、工具执行超时与错误消息截断等保护措施。

#### 3.3.5 Agent 模式写入闭环（Phase 3）

- 已新增 `patch_range` MVP，支持 `replace_text`、`insert_paragraph_after`、`set_paragraph_style`、`delete_paragraph` 四类安全写入操作。
- 已新增 `execute_script` 与 Roslyn 脚本执行器，作为复杂编辑场景的受控后备路径；其输入现已升级为 `write_code + verify_code` 双脚本协议，并接入静态安全校验。
- 已新增 `verify_script`，用于系统内部执行只读验证脚本，统一返回 `all_passed + results` 的结构化结果；该工具不暴露给模型，模型应通过写工具提交验证计划。
- 已补强写入工具契约说明与错误提示，明确 `patch_range.operations` 必须传真实 JSON 数组，`execute_script` 必须同时提供 `write_code` 与 `verify_code`，并明确 `patch_range` 默认应优先单步写入、批处理索引按实时文档顺序解释。
- 已补强 `execute_script` 约束，明确当前脚本环境只支持 dynamic COM 写法，且 Word COM 集合应使用 `Count + 1-based 下标循环` 访问，不能直接对 `Paragraphs`、`Rows`、`Cells`、`Shapes` 等集合使用 `foreach`。
- 已补强验证脚本约束，明确 `verify_code` / `verify_script.code` 必须保持只读，并返回包含 `all_passed` 与 `results` 的结构化结果。
- 已在 `AgentOrchestrator` 中接入文档可写性前置检查、写前确认等待、固定预算保护、步骤级 Undo 接入，以及“写入已执行 / 已验证生效 / 验证失败 / 待修复 / 暂停决策”事件透出。
- 已在编排层强制执行“写后验证”约束：任何写工具成功后，都必须经过正式验证步骤确认；只有验证通过才会发送真正的变更确认事件，否则会明确标记为“已执行但未验证”“验证失败”或“待修复”。
- 已在编排层加入“自动补验证”兜底：当模型漏掉显式验证步骤时，系统会优先基于当前写步骤生成可靠的自动验证脚本；自动验证通过则立即提交当前步骤，只有自动验证无法构建或未通过时才回退当前写步骤并进入修复/暂停链路。
- 已将系统自动验证结果改为 `role=user` 内部观察消息写入 LLM 上下文，不再把 `__auto_verify` 保存为 `role=tool` 历史；模型仍可看到验证通过、验证失败、验证工具异常等具体原因，同时避免下一轮请求出现孤立 tool 消息。
- 已为自动验证观察增加内部元数据，并调整为“提交/回滚完成后再写入”：验证通过时只发送短观察提示已提交并继续后续 Todo；验证失败或异常时发送详细观察，明确当前失败步骤已回退并提供验证输出。
- 已将单轮工具调用上限进一步提升到 20，并新增写步骤修复状态机：写工具失败后不允许直接正常结束任务，必须先修复当前步骤；若当前步骤连续失败 3 次或模型在待修复状态下提前结束，系统会只回退当前步骤、保留之前已验证成果，并进入暂停决策。
- 已补强 `execute_script` 提示词约束，允许根据任务复杂度适当拆分成多个脚本步骤；一个脚本可包含少量紧密相关的小操作，但多个独立修改目标应拆成多步“写一步 -> 验证一步 -> 再写下一步”执行。
- 已通过 `IConfirmationChannel + WebViewConfirmationChannel + SmartWordBridge` 打通真实的宿主确认回传链路，避免双 bridge 实例问题。
- 已将 Undo 回滚语义修正为“同文档尽量自动回滚，文档切换时仅做最佳努力并明确提示”。
- 已补齐 `UndoRecordWrapper` 中 `UndoRecord` COM 对象的显式释放，减少任务级写入反复执行时的 COM 生命周期泄漏风险。

### 3.4 LLM 接入、工具调用与模型能力分流

#### 3.4.1 OpenAI Compatible 基础接入

- 已实现 `OpenAiCompatibleClient`，支持兼容 OpenAI Chat Completions 协议的服务端接入。
- 已支持 SSE 流式读取与分片转发，可将模型输出实时推送到前端。
- 已支持工具调用请求体构造、`delta.tool_calls` 累积解析以及最终 `assistant` 消息拼装。
- 已将 `HttpClient` 收敛为共享实例复用，避免每次请求重复创建连接客户端。
- 已为共享 HTTP 客户端局部指定 TLS 1.2，不依赖 Word/其他 AddIn 修改的进程级 TLS 默认值，也不绕过证书校验；这解决了部分 VSTO 宿主中调用 SiliconFlow 时的“未能创建 SSL/TLS 安全通道”问题。

#### 3.4.2 多轮工具调用编排

- 已在 `AgentOrchestrator` 中实现多轮“模型回答 -> 工具调用 -> 工具结果回填 -> 再次请求模型”的基础循环。
- 已支持工具调用事件输出，包括开始、完成、拒绝、上下文压缩提示、任务完成等事件。
- 已支持将工具结果写入对话历史，形成后续推理可继续消费的消息序列。
- 已接入基于模型上下文窗口比例的分阶段压缩：默认按 256K 上下文窗口计算 soft/hard/emergency 阈值，先轻量裁剪旧工具结果，仍超 soft 阈值时调用 LLM 生成统一 Current Task Summary，并保留规则压缩作为兜底。
- 已统一 Ask / Plan / Agent 的压缩摘要结构，模式只作为程序硬状态影响下一步权限与工具选择；压缩后的上下文会始终保留第一条 user 消息，避免 Skill 使用提示、任务入口提示等系统注入上下文被摘要替代。
- 已新增程序硬状态注入：由代码强制保留当前文档、Todo Board、写步骤恢复状态、最近自动验证、回滚结果、修复次数和下一步安全约束；写入状态按当前实现表达为“已验证提交 / 待修复 / 已回滚”，不再把“未验证写入”作为长期状态。
- 已将 Todo Board 从压缩必需状态调整为 Agent 复杂任务的可选强状态源：Todo Board 为空时不会视为异常，简单 Agent 任务会继续依据真实用户目标、写入状态和自动验证观察生成任务记忆。
- 已强化压缩后的消息协议安全：压缩器只会重插真实用户消息，不会把 SmartWord 内部观察当作用户原始请求；孤立 tool 和未闭合 tool call 链会被规避或摘要化。
- 已适配 `verify_script` 内部质检语义：`verify_script` 不再作为模型可见工具历史延续，写后自动验证结果通过内部观察进入 Agent 压缩摘要，用于表达已提交、失败回滚和下一步修复要求。
- 已将 Ask / Plan / Agent 的固定轮次预算统一为 100，并在后端强制封顶到 100，避免不同入口出现 5 / 8 / 20 等分裂体验。
- 已真正落地 `MaxIterationsReached` 事件：Ask / Plan 命中预算后会明确停止本轮且不再误发 `TaskCompleted`，Agent 命中预算后会先保留进度并进入可信暂停态。
- 已补强 Plan 模式采访链路稳定性：当模型返回缺失 `tool_call.id` 的采访调用时，编排层会自动补齐稳定 ID；当同一轮因采访等待或状态切换而提前结束时，系统会为剩余 tool call 自动补写 skipped result，避免下一轮请求携带不完整的工具结果序列。
- 已把 Todo Board 接入 Agent 主循环：在 Agent 模式开始时会先加载或初始化任务板，并向前端发出 `TodoBoardReady` 事件。
- 已支持在 `todo_read` / `todo_write` 执行成功后，将最新任务板快照作为工具结果的一部分写回对话历史，使模型下一轮能够直接看到自己刚更新的计划板。
- 已将 Todo reminder 收敛为低频内部提醒：当前只把 `todo_write` 视为真正维护任务板的动作；探索阶段连续 8 个有效执行轮次未 `todo_write` 时才注入首次 reminder，后续 reminder 间隔提升为 10 轮，并发出 `TodoReminderInjected` 事件用于任务板同步。
- 已删除“写后未更新 Todo Board”的高优先级提醒；成功文档写入后不会再因为下一轮未立即 `todo_write` 而频繁打扰用户。
- 已将 reminder 注入顺序调整到补齐剩余 `tool(skipped)` 结果之后，保证模型看到的轮次边界更干净。
- 已支持 Plan -> Agent 过渡时通过 `activePlan` 将 `ExecutionPlan` 转成标准 Todo Board，避免执行阶段只依赖自然语言复述计划。
- 已将 Plan -> Agent 的默认 Todo 初始化策略改为总是按当前 `activePlan` 重建；普通 Agent 入口和暂停/恢复面板中的显式用户决策仍保持原有恢复逻辑。
- 已修正 `todo_write` 的生命周期分类：它被归类为 SmartWord 状态写入，不再触发 Word 文档写入确认，也不再被误纳入文档写入专属的 `UndoScope + 写后验证 + 待修复回滚` 状态机，避免 Todo 同步步骤误触发“验证失败”并连带回滚已确认的文档改动。
- 已扩展权限模型为 `ReadOnly / ConfirmWrites / AutoSafeWrites / FullAuto` 四档：默认新用户为写入前确认，旧关闭确认配置迁移为自动安全写入，`FullAuto` 仅在用户显式选择时启用；`patch_range` 与 `execute_script` 分别按文档补丁写入和脚本写入裁决。
- 已补充取消执行链路：宿主桥接可取消当前运行并清理 pending 确认、采访问题和 Todo 恢复决策；编排层在取消时停止后续工具，当前未验证写步骤会回滚或恢复到最近可信检查点，已验证写入保留。
- 已通过 Prompt 工程降低简单任务工具调用：SYSTEM 增加工具调用克制原则，ASK 不再强制先 `probe_document`，AGENT 明确简单任务不需要 Todo Board 且同类安全改动应合并到一次 `patch_range.operations`，PLAN 避免把微小操作拆成过细 Todo。
- 已将 Todo Board 升级为带运行状态的执行对象：Agent 启动时会显式标记 `Running`，成功完成后自动删除持久化文件，异常、取消、待修复终止和崩溃样残留统一转入 `RecoveryRequired`，模型只会消费已确认可用的任务板。
- 已新增 Todo 恢复握手机制：当检测到 `RecoveryRequired` 或上次停留在 `Running` 时，编排器会先发出 `TodoBoardRecoveryRequired` 事件，等待前端决策完成后再发 `TodoBoardReady` 并进入正常主循环。
- 已在 Todo 生命周期中新增 `Paused / PausedByBudget`：当 Agent 只是跑到 100 轮预算上限且当前状态可信时，系统会保留 Todo 文件、不删板、不冒充完成，并允许用户后续继续尝试、跳过当前步骤或停止任务。
- 已为 Todo Board 增加“可信检查点 + 当前写步骤快照”元数据：每次真实写入前都会固化任务板快照，写后验证通过才提交为新的可信检查点；若当前步失败回退，Todo Board 会同步恢复到该快照，避免前端显示漂移进度。
- 已将“恢复旧任务板”语义修正为恢复最近可信快照，而不是沿用失败前的漂移板；这使得当前步回退、异常中断和崩溃样残留后的前端展示更接近真实文档状态。
- 已进一步把“最近可信提交快照”从运行态板子中独立出来：当前写步骤开始时会以该快照作为回退锚点，验证失败、暂停、恢复旧板时都优先从最近可信快照还原，而不再盲目信任运行中板子的临时状态。
- 已修正可信快照恢复策略只回滚任务项进度，不回滚 reminder 计数、写后待同步标志等当前轮次运行态字段，避免回滚一次后把后续 reminder 链路意外吞掉。

#### 3.4.3 引用映射与溯源数据

#### 3.4.4 模型能力分流

- 已实现基于模型能力的自动分流，不再单纯依赖人工切换模型。
- 已支持判断模型是否支持工具调用，以及是否要求回放 `reasoning_content`。
- 当前已内置的能力规则包括：
  - `DeepSeek-V3.2`、`GLM-4.7`：支持工具调用，并要求在工具链路中回放 `reasoning_content`
  - `*Speciale*`：按不支持工具调用处理
  - 其他模型：默认按支持标准工具调用处理

- 当首选与备选模型都不支持工具调用时，系统会自动降级为纯文本回答模式，并在提示词中明确要求模型说明“无法读取当前 Word 文档内容”。

#### 3.4.6 Skill Prompt 注入

- 已支持两类激活方式：前端显式选择 Skill，以及用户消息中的 `/skill name` 或 `@name` 显式引用。
- 已在 Skill prompt 中加入 SmartWord 专属安全声明：Skill 只是 Word 文档工作流上下文，不授予任意 shell 权限；`scripts/` 只能通过 `skill_run_script` 受控执行；所有 Word 修改仍必须通过 SmartWord 现有写入工具、权限确认、Undo、验证和任务历史审计链路。

#### 3.4.7 Skill scripts 受控执行

- 已新增 `skill_run_script` 工具，仅在 Agent 模式对模型可见；Ask / Plan 模式仍只暴露只读工具。
- 已新增 `SkillScriptInfo`、`SkillScriptRunRequest`、`SkillScriptRunResult`、`SkillScriptApprovalKey` 等 Core 契约，并扩展 `ISkillStore` 支持列出脚本、解析脚本绝对路径和计算 SHA-256。
- 已实现 `SkillScriptRunner`，支持 C# `.csx` 与 Python `.py` 脚本；每次运行创建临时 workspace，将用户确认输入复制到 `inputs/`，将脚本产物收集自 `outputs/`，并返回 stdout、stderr、exit code、duration、outputs、result_json 和 warnings。
- 已新增独立 `SmartWord.SkillHost.exe`，每次脚本调用在独立进程中执行，由 Windows Job Object 管理进程树；超时、取消或宿主异常不会把脚本留在 Word AddIn 进程内。宿主隔离不是 AppContainer 等完整 OS 沙箱，外部代码仍按不可信代码处理。
- C# Skill 脚本使用专用 globals，仅暴露 `ArgumentsJson`、`WorkspacePath`、`ReadInputText`、`WriteOutputText`、`WriteJsonResult`、`Write` 等受控 API，不复用 Word COM `execute_script` 的 `WordApp / ActiveDoc` 环境。
- Python 脚本通过 `python.exe <script> --args <json>` 执行，解释器从 `PATH` 探测；找不到时返回明确错误，不自动安装第三方依赖，不注入 API Key。
- 已加入默认禁止联网的应用层防护：C# 静态拦截 `System.Net`、`HttpClient`、`WebClient`、`Socket`、`System.IO`、`Process`、Office COM 等高风险访问；Python 静态拦截 `socket`、`requests`、`urllib`、`http.client`、`subprocess`、`os.system`、`ctypes`、`win32com` 等模块/调用。
- 已限制单个脚本最大 256KB、输入 200MB、输出 100MB、输出文件最多 1000 个，stdout/stderr 各保留 64KB，脚本默认 30 秒超时；每次调用结束清理 workspace，并在启动时清理 24 小时前残留。
- 已新增 `FileSkillScriptApprovalStore`，将用户“记住此 Skill 脚本授权”的结果保存到 `%AppData%\\SmartWord\\skills\\skill-script-approvals.json`；授权键按 Skill 来源、Skill 内容哈希、脚本路径/hash、runtime 和输入/输出权限集细化，任一能力边界变化后自动失效。
- 已扩展确认通道为 `IToolConfirmationChannel`，保持旧布尔确认兼容，同时支持“本次允许 / 记住授权”；Agent 编排层会在已授权脚本上跳过确认，未授权脚本即使处于 FullAuto 也需要先确认。
- `skill_run_script` 结果已作为普通工具结果写入 conversation history，并通过现有 `ITaskHistoryStore` 进入 SQLite 任务历史审计；脚本不能直接修改 Word，后续 Word 修改仍需走 `patch_range` / `execute_script` 与自动验证状态机。

- 已为 Skill 存储增加安全护栏：Skill 名称仅允许小写字母、数字和连字符；所有读写删除操作均校验根目录边界；`SKILL.md` 限制 64KB；保存时对明显 API Key、Bearer Token、Authorization 头等密钥做最小脱敏；内置 Skill 不允许删除。
- 已按主流 Agent Skill 结构支持 `references/`、`assets/`、`scripts/` 资源目录；`scripts/` 会列出 runtime、大小和 SHA-256，执行必须通过 `skill_run_script` 的受控路径与授权流程。
- 已增加受控 `read_skill_resource` 只读工具：只允许当前 Active Skill 的 `references/` 和文本型 `assets/`，拒绝绝对路径、链接路径、目录越界和二进制内容注入。
- 已在 AddIn Bridge 暴露 `GetSkillsJson`、`GetSkillDetailJson`、`CreateSkillJson`、`SaveSkillJson`、`DeleteSkillJson`、`SetSkillEnabledJson`，并在 `SendMessageAsync` 中解析 `selectedSkillNames` 注入运行选项。
- 已在 AddIn Bridge 暴露 `GetSkillScriptApprovalsJson` 与 `RevokeSkillScriptApprovalJson`，用于前端查看和撤销已记住的脚本授权。
- 已在 Bridge 增加 Skill 脚本策略、版本化保存和本地观测摘要接口；保存时按内容 SHA-256 检测并发修改，脚本/来源/内容哈希变化会使旧授权失效。

#### 3.6.3 当前阶段边界

- 当前已完成 Ask 模式只读链路与 Agent 模式最小写入闭环，`patch_range + 自动验证脚本` 与 `execute_script(write_code + verify_code)` 双路径均已落地，且编排层已能强制写后验证、按步骤提交已验证成果、在当前步失败时只回退当前步并转入暂停决策。
- Agent 提示词已进一步收紧脚本生成规范：`write_code` 与 `verify_code` 必须共享同一段目标筛选逻辑，禁止空 `catch {}`，验证脚本必须使用局部变量并在最后统一 `return new { all_passed = allPassed, results = results };`，且明确要求“写什么属性就验证什么属性”。
- Agent 提示词已补充常见格式操作模板片段，包括“首行缩进 2 字符”“段前/段后”“行距”“字体名/字号”，并明确当写后验证失败时应优先使用 `read_script` 对失败段落做只读探针，再生成修复脚本。
- 当写步骤处于“待修复”状态时，编排层已为 `read_script` 开放特权：模型可先用 `read_script` 做只读探针分析失败对象共性，再于下一轮提交修复脚本；其它普通只读工具在该状态下仍会被拒绝。
- 编排层单轮工具调用上限已从 10 提升到 20，并补充了相应自动化测试与提示词契约测试。
- 运行预算当前采用“固定 100 轮”策略：它优先解决用户频繁被打断的问题，并通过暂停态收尾避免未完成任务被误判为成功；更细粒度的 token / 时间 / 工具预算仍可在后续迭代中继续引入。

- Todo Board 当前采用 JSON 文件方案，尚未接入 SQLite，也尚未扩展到多文档并发协作、跨设备同步等更高阶场景。
