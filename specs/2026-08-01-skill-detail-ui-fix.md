# Skill 详情数据契约与窄栏布局修复

## 需求背景

用户导入包含较长 `SKILL.md`、大量脚本及附属文件的外部 Skill 后，详情页直接展开完整源码和所有资源，280-320px 的 Word 任务窗格被长内容占满。同时，C# Bridge 直接序列化 `SkillResource` 和 `SkillScriptInfo`，输出 PascalCase 字段，而 Vue 按 camelCase 读取，导致资源和脚本显示为重复的 `/`、`/ / · 未授权`。

## 目标

1. 修复资源和脚本字段为空的问题，建立稳定的 camelCase Bridge 契约。
2. 详情页以 Skill 摘要和安全状态为首要信息，默认收起完整 Markdown 源码。
3. 资源和脚本使用紧凑、可扫描的列表，并对长列表提供展开/收起。
4. 在 280px 宽任务窗格中不产生横向溢出或超长空白区域。

## 修改范围

- `WebViewBridge`：显式映射 Skill 详情、资源和脚本响应字段。
- `hostBridge`：兼容归一化 camelCase/PascalCase Skill 详情字段。
- `skills` Store：统一通过归一化详情更新状态。
- `SkillPanel`：重构详情摘要、源码编辑器、资源及脚本列表布局。
- 前端生产构建产物和已实现功能文档。

## 不在范围

- 修改 Skill 导入、执行、授权或内容哈希规则。
- 修改已经导入的 `xlsx` Skill 文件。
- 新增 Markdown 所见即所得编辑器或完整文件管理器。
- 允许直接执行 `scripts/` 下的任意附属文件。

## 实现方案

1. C# 端新增 Skill 详情响应映射方法，将 `relativePath`、`kind`、`sizeBytes`、`isText`、`runtime`、`sha256` 等字段固定为 camelCase。
2. 前端 Bridge 对两种字段大小写做兼容归一化，避免前端静态资源与旧 AddIn 宿主短暂版本不一致时再次显示空值。
3. Skill 详情默认展示名称、来源/版本、说明和包统计；完整 `SKILL.md` 通过“查看源码/收起源码”控制。
4. 资源列表仅展示 `references`、`assets` 等非脚本资源；脚本区域展示可执行脚本，并单独显示 `scripts/` 附属文件数量。
5. 资源和脚本默认只展示少量条目，用户可展开全部；路径允许换行，哈希使用短值和原值 tooltip。

## 测试计划

- 验证 PascalCase 和 camelCase 详情响应均能归一化为正确字段。
- 使用包含多个资源和脚本的外部 Skill 数据检查详情页路径、运行时、授权状态和数量。
- 在 280px 和 320px 宽度检查无横向溢出，长路径不会撑破布局。
- 运行前端生产构建和 `build.ps1 -AddIn`。
- 运行 Skill Store/Application 相关回归测试。

## 风险与注意事项

- 默认收起源码会增加一次点击，但显著降低进入详情后的信息噪声；编辑能力仍完整保留。
- 隐藏脚本附属文件明细可能降低排查便利性，因此保留数量摘要，并继续列出所有可执行 `.py`/`.csx` 脚本。
- 前后端双重归一化有少量重复，但可降低宿主与静态前端版本短暂不一致造成的兼容风险。
