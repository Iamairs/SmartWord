# 文档事实问答强制首轮工具调用

## 需求背景

日志显示 Ask 模式已启用 9 个工具，但“总结这篇文档的内容”请求中模型返回 `ToolCallCount=0`，导致后端没有工具事件，前端也无法显示调用轨迹。仅靠提示词要求模型刷新证据，对部分 OpenAI 兼容模型不够稳定。

## 目标

- Ask 模式的文档事实类问题首轮必须产生真实工具调用。
- Plan 模式依赖文档事实时同样获得首轮工具调用保障。
- 普通闲聊或与文档无关的问题继续允许直接回答。
- 复用 OpenAI 兼容协议标准 `tool_choice=required`，不伪造前端轨迹。

## 修改范围

- Core LLM 严格工具选择扩展接口与运行选项。
- OpenAI 兼容客户端请求体。
- 遥测 LLM 装饰器和单轮执行器。
- Ask / Plan 首轮文档事实判定。
- 相关单元测试和功能文档。

## 不在范围

- 不暴露模型私有思维链。
- 不强制所有 Ask 问题调用工具。
- 不改变 Agent 写操作、权限确认或验证流程。

## 实现方案

1. 新增可选的严格工具选择接口，避免破坏现有 `ILlmClient` 实现和测试替身。
2. OpenAI 兼容客户端在严格模式下发送 `tool_choice: required`，否则保持 `auto`。
3. 编排器识别 Ask/Plan 中依赖当前文档事实的请求，仅在第一轮设置严格工具选择。
4. 后续轮次恢复 `auto`，允许模型在读取证据后输出最终答案或计划。
5. 增加请求体、模式判定和执行路径测试。

## 测试计划

- 运行 OpenAI 请求体测试。
- 运行 Agent 编排相关测试。
- 运行 `git diff --check`。

## 风险与注意事项

- `tool_choice=required` 是 OpenAI 兼容协议标准字段，但少数非标准服务可能不支持；严格模式只用于已经判定支持工具调用的模型。
- 文档事实判定需保持保守，只覆盖明确提及文档、段落、章节、选区、表格、批注、总结等场景。
