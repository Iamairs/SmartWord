# 分支与 Spec 优先开发流程

> 日期：2026-07-25
> 类型：docs
> 状态：已完成

## 背景

团队希望后续所有开发修改都遵循更严格的分支、规格文档、测试、提交、PR 合并和推送流程，避免直接在主分支修改代码，也避免无规格说明的实现变更。

## 目标

1. 开发或修改代码前，必须先从主分支拉出规范命名的新分支。
2. 修改前必须在 specs 目录中新建本次任务的 spec 文档。
3. spec 文档需要说明需求背景、修改范围、实现方案、测试计划和风险。
4. 完成修改后必须先运行相关测试，测试通过后才能提交。
5. 提交必须遵循原子化提交和中文提交信息规范。
6. 代码合入主分支必须通过 PR。
7. PR 合并到主分支后必须推送远端。
8. 不得把无关未提交改动混入本次分支、提交或 PR。

## 本次修改范围

- 更新根目录 AGENTS.md，补充“分支与 Spec 优先开发流程”。
- 新增本 spec 文档，作为本次文档变更记录。

## 不在本次范围

- 不修改生产代码。
- 不修改测试代码。
- 不处理当前已有的 benchmark 未提交修改。

## 验证计划

- 运行 git diff --check，确认 Markdown 与空白格式无明显问题。
- 检查 git status，确认只提交本次文档相关文件。

## 验证结果

- git diff --check 通过。
- AGENTS.md 和本 spec 均可按 UTF-8 正常读取。
- 已确认 AGENTS.md 包含分支命名、spec 文档、测试、精准提交、PR 合并和远端主分支更新规则。

## 风险与注意事项

- 当前仓库已有一处 benchmark 未提交修改，需要继续保留，不得纳入本次提交。
- 如果本地 GitHub CLI 不可用或未认证，PR 创建/合并可能需要用户在 GitHub 页面完成。
