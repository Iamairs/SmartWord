# 网络 Skill 安装与多文件夹导入

## 需求背景

SmartWord 当前只能在应用内创建 Skill，或由用户手动把外部目录复制到 `%AppData%\SmartWord\skills`。这种方式要求用户理解目录结构、下载和解压流程，也缺少安装前的来源、内容和风险确认。用户希望直接安装网络上的 Skill，并补充支持从指定本地文件夹导入多个 Skill。

上一阶段已经建立外部 Skill 信任级别、脚本默认禁用、路径防护、内容哈希和原子保存。本功能在这些边界内降低安装门槛，不能把“安装 Markdown 工作流”隐式升级为“允许执行远程代码”。

## 目标

1. 在 Skill 面板提供统一的“导入 Skill”入口。
2. 支持 GitHub 公共仓库地址、GitHub Release ZIP 地址和普通 HTTPS ZIP 地址。
3. 支持从本地指定文件夹导入，并可在一个批次中添加、预览和安装多个文件夹。
4. 安装前展示名称、版本、来源、资源/脚本数量、所需工具、内容哈希、校验错误和风险提示。
5. 通过下载限制、安全解压、目录校验、临时目录清理和原子移动避免不完整安装及常见压缩包攻击。
6. 所有网络和本地导入的 Skill 强制标记为外部来源，脚本默认禁用。

## 修改范围

### 1. 导入来源

- 网络来源：
  - `https://github.com/<owner>/<repo>` 公共仓库地址，默认下载仓库默认分支的 ZIP；
  - GitHub `archive`、`releases/download` 等直接 ZIP 地址；
  - 其他 HTTPS ZIP 地址。
- 本地来源：
  - 用户通过系统文件夹选择器逐次添加目录；
  - 待导入列表可同时保留多个目录，并统一预览、确认和安装；
  - 每个目录必须是独立 Skill 根目录，根目录直接包含 `SKILL.md`；
  - 导入采用复制，不依赖或修改原目录。
- 网络下载仅支持无需登录的公开资源；第一版不接收 Token、Cookie 或 GitHub 私有仓库凭据。

### 2. 两阶段安装流程

1. `Preview` 阶段将网络包下载到独立临时目录，或只读检查本地源目录。
2. 安全解压后识别 Skill 根目录：允许 ZIP 根目录直接包含 `SKILL.md`，或仅有一层仓库包装目录且该目录直接包含 `SKILL.md`。
3. 使用与 `FileSystemSkillStore` 一致的 frontmatter 和路径规则解析 Skill。
4. 返回安装预览，包括来源、名称、显示名、版本、说明、内容哈希、总文件数、总容量、资源数、脚本数、所需工具、警告和可安装状态。
5. 前端只有在用户明确确认后提交 `Install`；安装请求绑定预览会话 ID，不接受前端提供任意临时路径。
6. 每个预览会话有短期有效期，并在安装、取消、超时或进程下次启动时清理。
7. 多文件夹批次按条目返回结果；无效项不阻止用户安装其他有效项。

### 3. 安全与容量限制

- 仅允许 HTTPS；拒绝 URL 中的用户名、密码和非默认端口。
- URL 与每次重定向目标都必须解析到公网地址；拒绝环回、链路本地、私网 IPv4/IPv6 和无解析结果的主机，避免通过安装器访问本机或内网服务。
- 网络请求总超时 30 秒，最多 5 次重定向；每次重定向重新校验协议和目标。
- 下载压缩包最大 20 MB；响应声明或实际读取超限均立即停止。
- 解压后最大 100 MB、最多 1000 个文件、单文件最大 20 MB、目录深度最大 16 层。
- 拒绝 ZIP Slip：`..`、绝对路径、盘符路径、解压根目录越界和重复覆盖路径。
- 拒绝 ZIP 中的符号链接标记；本地导入拒绝符号链接、Junction 和其他 reparse point。
- 拒绝缺少、超限或无法解析的 `SKILL.md`，并沿用 64 KB Markdown 上限和 Skill 名称规则。
- 安装前重新计算源内容哈希；本地目录在预览后变化时拒绝安装并要求重新预览。
- 安装使用用户 Skill 根目录下的暂存目录，完成复制和二次校验后原子重命名为正式目录。
- 安装失败清理暂存目录；启动或新预览时清理超过 24 小时的安装临时目录和预览会话。

### 4. 信任、冲突和更新策略

- 所有导入项强制使用：
  - `trust_level: external`；
  - `script_policy: disabled`；
  - `source: <原始 HTTPS URL 或规范化本地目录来源>`。
- Store 不信任外部 `SKILL.md` 自己声明的 `built_in`、`user` 或脚本策略。
- 外部 Skill 不得覆盖或冒充内置 Skill。
- 同名用户 Skill 第一版默认拒绝安装，并在预览中明确显示冲突；不提供静默覆盖。
- 第一版不自动更新，也不在启动时访问网络；用户后续可重新导入不同名称的版本。
- 内容哈希覆盖 `SKILL.md` 及资源/脚本文件，以便内容变化后旧脚本授权自然失效。

### 5. 分层与接口

- Core 新增安装来源、预览、预览项、安装请求和安装结果模型，以及 `ISkillPackageInstaller` 接口。
- Infrastructure 新增：
  - HTTPS/GitHub URL 规范化和受限下载；
  - 安全 ZIP 解包；
  - 本地目录只读扫描与受限复制；
  - 预览会话存储、TTL 清理和原子安装；
  - 与现有 Skill frontmatter 解析规则复用的包校验器。
- AddIn Bridge 新增选择本地文件夹、网络预览、本地批量预览、确认安装和取消预览接口。
- Vue Skill 面板新增紧凑的导入视图，支持网络 URL、文件夹待选列表、逐项校验结果、风险摘要和批量确认。

## 不在范围

- 在线 Skill 市场、搜索、评分、推荐榜单和后端服务。
- 自动更新、后台检查更新、差异合并和降级。
- 私有 GitHub/GitLab 仓库、鉴权下载、SSH 或 Git 克隆。
- HTTP、FTP、本地 UNC 网络共享和任意协议处理器。
- Python、npm、NuGet 等依赖解析或自动安装。
- 企业签名、证书链、发布者认证和恶意代码扫描服务。
- ZIP 内同时安装多个 Skill；一个网络包对应一个 Skill。
- 在一次原生文件夹对话框中多选目录；为保持依赖和兼容性成本可控，用户通过“添加文件夹”连续加入多个目录后批量处理。
- 自动开启外部 Skill 脚本；用户仍需在现有详情页显式调整脚本策略并逐次授权。

## 实现方案

1. 扩展 Core 安装模型和接口，保持 `ISkillStore` 的现有 CRUD 契约不变。
2. 抽取或开放现有 frontmatter/路径校验能力，使 Store 与安装器采用一致规则。
3. 在 Infrastructure 实现 `FileSystemSkillPackageInstaller`，以不可猜测的会话 ID 管理短期预览目录。
4. 下载使用单独的 `HttpClientHandler`，关闭自动重定向并手动校验每一跳；GitHub 仓库地址转换为公开 ZIP 下载地址。
5. ZIP 逐条目检查后解压，不调用无边界的一键解压 API；本地目录使用受限递归扫描和复制。
6. 安装前把强制信任元数据写入独立状态文件，由 Store 读取覆盖外部 manifest 声明；避免为了加字段而改写第三方 `SKILL.md` 正文。
7. AddIn 组合根注册单例安装器；Bridge 仅传递预览会话 ID 和选中条目 ID，不暴露临时目录。
8. 前端以单一导入区承载“网络”和“文件夹”两种模式，窄屏中逐项纵向展示，不使用嵌套卡片和横向滚动。

## 测试计划

### Core/Infrastructure

- GitHub 仓库 URL、GitHub ZIP 和普通 HTTPS ZIP 规范化正确；HTTP、凭据 URL、非 ZIP 和非法地址被拒绝。
- 下载声明超限、流式读取超限、超时、重定向过多及重定向到非 HTTPS 被拒绝。
- ZIP Slip、绝对路径、盘符、重复路径、符号链接、文件数/容量/深度超限被拒绝。
- ZIP 根目录和单层仓库包装目录均能识别；缺失或多层歧义 `SKILL.md` 被拒绝。
- 本地多目录预览逐项返回结果；不存在目录、reparse point、根目录缺少 `SKILL.md` 和预览后变化被拒绝。
- 同名用户 Skill、内置 Skill 冲突和非法 Skill 名称被拒绝。
- 外部信任级别、来源和脚本禁用策略无法被包内容覆盖。
- 安装成功后目录完整可读；失败不留下正式目录；会话取消、过期和异常路径均清理临时文件。

### AddIn/Web

- Bridge 的预览、安装、取消和错误 JSON 契约稳定。
- 文件夹选择取消不会产生空条目；连续添加多个目录可统一预览。
- 用户必须看到风险提示并显式确认后才能安装。
- 有效项与失败项能在同一批次中区分，安装完成后刷新 Skill 列表。
- 280px 宽度下 URL、路径、哈希和错误消息不会撑破布局。
- 前端生产构建、Core 测试、AddIn 构建和现有 Skill 管理回归通过。

## 风险与注意事项

- HTTPS 只能保护传输过程，不能证明发布者可信；UI 必须展示原始来源和内容哈希，不得使用“安全”或“已验证发布者”等误导文案。
- ZIP 的压缩后体积很小但解压后很大，必须以逐条目实际写入量执行总容量限制，不能只依赖 ZIP 元数据。
- GitHub 默认分支下载地址可能发生重定向或仓库不存在；错误信息应区分地址无效、网络失败、访问受限和包格式错误。
- 本地源目录可能在预览与安装之间变化，因此安装前必须复核哈希；代价是大目录会扫描两次，但默认 100 MB 上限使损耗可控。
- 为每个预览保留网络 ZIP 会占用临时空间；会话 TTL、主动取消和启动清理必须同时存在。
- 批量安装不做全批次事务：某一项失败时已成功项保留，并给出逐项结果。这减少复制回滚损耗，也符合用户选择多个互不相关 Skill 的预期。
- 独立 SkillHost 不是完整 OS 强沙箱；即使用户日后显式开启外部脚本，仍需现有授权与风险提示。

## 验收标准

- 用户可以粘贴受支持的公开 HTTPS/GitHub 地址，看到安装预览并确认安装 Skill。
- 用户可以连续添加多个本地 Skill 文件夹，在同一批次中看到逐项结果并安装所有有效项。
- 网络或本地导入不修改源内容，正式 Skill 目录仅在完整校验后出现。
- 恶意或超限 ZIP、越界/链接目录、同名冲突和预览后变化均被拒绝且不残留临时文件。
- 所有导入 Skill 显示为外部来源，脚本默认禁用，安装过程不会执行包内脚本或安装依赖。
- 现有 Skill 创建、编辑、启停、推荐、资源读取和脚本授权行为保持通过。
