# 修复工具调用轨迹不可见

## 需求背景

工具调用轨迹改为折叠时间线后，实际对话中用户看不到调用了哪些工具。当前轨迹组件绑定的是全局 `activeToolCalls`，且渲染在消息列表最顶部。最终回答内容较长时，轨迹会停留在列表顶部并被滚动位置遮挡；新一轮请求开始还会清空该全局数组。

## 目标

- 工具调用轨迹必须在对应助手回答附近可见。
- 最终回答完成后，仍能展开查看本轮调用过的工具。
- 保留折叠态“处理中/已处理 + 耗时”的设计。
- 不改变后端工具调用协议。

## 修改范围

- `web/SmartWord.WebClient/src/stores/chat.js`
- `web/SmartWord.WebClient/src/components/ChatWindow.vue`
- 前端构建产物
- `docs/已实现的功能.md`

## 不在范围

- 不修改 C# 后端事件协议。
- 不展示模型私有思维链。
- 不调整工具执行逻辑。

## 实现方案

1. 在前端 store 中增加当前助手消息关联逻辑。
2. 工具调用开始或完成时，把 `activeToolCalls` 快照同步到最近的助手消息。
3. 渲染消息时，如果助手消息携带工具轨迹，则在该消息正文前显示 `ThoughtActionTrace`。
4. 移除消息列表顶部的全局轨迹渲染，避免轨迹和回答脱节。

## 测试计划

- 运行 `npm run build`。
- 运行 `git diff --check`。
- 用本地测试页模拟“工具调用 + 长回答”，验证轨迹出现在助手消息内且可展开。

## 风险与注意事项

- 流式回答开始前可能先出现工具调用，因此同步快照时需要确保存在可承载轨迹的助手消息。
- 纯文本回答没有工具调用时，不应出现空轨迹。
