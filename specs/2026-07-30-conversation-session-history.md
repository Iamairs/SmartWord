# 新会话历史隔离

## 需求背景

用户在前端开启新会话后，Ask 请求日志仍显示 `MessageCount=196`。当前 `IConversationStore` 仅按文档路径持久化和读取消息，前端界面清空后端历史不会随之切换，导致同一文档的旧对话和工具结果被继续发送给模型。

## 目标

- 每个前端聊天会话拥有稳定且独立的 `conversationId`。
- 同一聊天会话内的连续提问继续共享历史。
- 新会话不再加载同一文档的旧消息。
- Plan 转 Agent 时按既有规格建立新的执行会话上下文。
- 任务历史、Todo Board 和文档一致性检查仍使用真实文档路径。

## 修改范围

- 前端聊天状态和发送请求。
- WebView2 Bridge 请求解析。
- Agent 运行选项与对话存储键生成。
- 编排器读写对话历史的位置。
- 相关前后端测试和功能文档。

## 不在范围

- 不删除既有 SQLite 对话记录。
- 不改变任务审计历史的文档维度。
- 不改变工具调用轨迹的前端展示样式。

## 实现方案

1. 前端初始化聊天状态时生成 `conversationId`，同一会话的请求复用该值。
2. Plan 转 Agent 清空聊天上下文时同步生成新的 `conversationId`。
3. Bridge 将 `conversationId` 写入 `AgentRunOptions`。
4. 编排器仅在访问 `IConversationStore` 时使用“文档路径 + conversationId”组成的存储键，其他文档级能力继续使用真实路径。
5. 未携带 `conversationId` 的旧调用保持按文档路径工作的兼容行为。

## 测试计划

- 测试相同文档不同会话的历史隔离。
- 测试同一会话的连续消息共享。
- 测试空 `conversationId` 的兼容行为。
- 运行 Core、前端测试与构建，并执行 `git diff --check`。

## 风险与注意事项

- 会话 ID 必须只影响对话消息存储，不能污染任务历史、Todo Board 或文档路径日志。
- 前端页面重新初始化会创建新会话，因此不会自动恢复上次页面中的聊天上下文；历史任务仍可从任务历史面板查看。
