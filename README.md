# SmartWord

## 让 AI 直接在 Word 里工作

Word 最难的，往往不是写出一句话，而是把一整份文档处理好：找到所有相关位置、保持格式一致、改完不漏项，还要确认没有误伤原文。

SmartWord 是装在 Microsoft Word 里的 AI 文档副驾。你直接用自然语言交代任务，它会读取当前文档的结构和内容，在 Word 中定位目标、完成工作，并把结果交回给你检查。

> “把这份报告的摘要改得更适合给管理层阅读。”
>
> “找出全文中‘客户’和‘用户’混用的地方，先列清单，不要修改。”
>
> “把所有一级标题统一成现在第一章的格式，改之前让我确认。”

这不是把文字复制到另一个聊天窗口再复制回来，而是让 AI 在文档现场完成从理解、定位到修改和检查的完整工作。

## Word 用户真正头疼的事

| 你现在遇到的难题 | SmartWord 的不同做法 |
| --- | --- |
| 文档太长，无法完整粘贴给 AI | 直接读取当前 Word 文档，按章节、段落、表格和选区获取相关内容 |
| 知道要改什么，却找不到全文所有位置 | 在文档中搜索并返回出处，点击回答即可跳回对应位置 |
| 改一处容易，改几十处既慢又容易漏 | 按统一规则批量处理段落、标题、术语和常见格式 |
| AI 只会给建议，真正落地还得手工操作 | 在 Word 内执行替换、插入、删除和格式整理 |
| 自动化很方便，但怕改错正式文档 | 改之前说明影响范围并等待确认，改之后自动检查，出问题可回退当前步骤 |
| 宏和脚本能做，但学习和维护成本太高 | 用自然语言描述目标；复杂任务可以先生成计划，再按步骤执行 |

## 它能替你完成什么

### 读懂整份文档

- 总结全文、章节或当前选区
- 从长文档中提炼要点、行动项和待确认风险
- 解释复杂条款、段落和表格内容
- 查找关键词、正则表达式、术语和重复表达
- 阅读标题结构、表格、批注、页眉和页脚
- 在回答中标出出处，点击即可回到 Word 原文

### 修改文字而不是只提建议

- 润色、压缩、扩写、改成正式或更易懂的表达
- 检查错别字、病句、重复和术语不一致
- 按上下文统一全文的称呼、语气和写作风格
- 在指定选区或明确范围内替换原文、插入段落、删除内容

### 一次整理一整类格式

- 统一标题层级、段落样式、字体和字号
- 检查常见排版问题，生成问题清单
- 处理批注和文档待办事项
- 对涉及多个章节或表格的任务先规划，再连续执行

## SmartWord 的工作方式

一次任务通常会经历下面的过程：

1. **理解现场**：读取当前文档、光标或选区，确认任务涉及的范围。
2. **给出依据**：需要查证时先返回文档出处和相关上下文，而不是凭空猜测。
3. **提出方案**：简单任务直接处理；复杂任务先列出步骤和风险。
4. **执行改动**：只处理你允许的范围，批量任务保持统一规则。
5. **检查结果**：重新读取被修改的内容，确认文字或格式确实达到目标。
6. **交付控制权**：展示完成的改动和任务记录；你可以继续、暂停、跳过当前步骤或停止任务。

你可以把它当作三种节奏来使用：

- **先问清楚**：只读总结、检查和查找，不改变文档。
- **先列计划**：适合合同、报告、论文等范围较大的整理任务。
- **直接处理**：适合明确、重复、影响范围较小的修改。

## 让它改文档，也让你放心

SmartWord 的价值不只是“会写”，而是让修改过程可控：

- 选中文本时优先处理选区，避免一句话变成全文修改。
- 每次写入都显示要改哪里、做什么以及是否可以撤销。
- 写入后自动回读验证；没有验证通过的结果不会直接当成完成。
- 验证失败、任务取消或文档被切换时，优先回退当前写入步骤。
- 只读、受保护或不可编辑的文档不会被强行修改。
- 重要文档仍建议先另存副本；自动检查不能替代人工审阅。

## 从一次选区开始

最容易感受到 SmartWord 差异的方式，是先选中一段文字，然后提出一个具体要求：

```text
把这段话压缩到 100 字以内，保留事实和数字。
```

```text
解释这段合同条款对乙方的风险，并引用上下文。
```

```text
把这段内容改成正式商务表达，先给我建议，不要写回文档。
```

当任务需要处理全文时，直接说清范围和目标即可：

```text
检查全文的术语一致性，列出原文位置、当前写法和建议写法，不要修改。
```

## 可复用的工作流

把经常重复的要求保存成 Skill，就能把一次性的提示变成团队可复用的文档流程。例如：

- 交付前检查报告结构、标题和格式
- 按公司规范润色业务报告
- 检查合同中的专有名词和称谓

SmartWord 自带 `document-finalizer`、`business-report-polish` 和 `term-consistency-check`。你也可以在 Skill 页面创建自己的规则，或导入本地文件夹、公开 GitHub 仓库和 HTTPS ZIP 中的工作流。

第三方 Skill 的脚本默认关闭，运行前需要单独授权。请确认来源和用途后再启用，不要运行来源不明的脚本。

## 开始使用

如果你使用的是本仓库源码，需要在 Windows 上构建 Word 加载项：

- Microsoft Word 2016 或更高版本
- .NET Framework 4.7.2
- Visual Studio 2022 或 Build Tools，并安装 Office/SharePoint 开发工具和 VSTO Runtime
- 一个 OpenAI 兼容格式的模型服务（云端或本地）及 API Key

在仓库根目录执行：

```powershell
.\build.ps1 -Frontend
.\build.ps1 -AddIn
```

然后在 Visual Studio 中启动 `src/SmartWord.AddIn`，打开 Word 后点击功能区中的 **SmartWord**。首次打开侧边栏时，在设置中填写模型服务地址、模型名称和 API Key，并先进行连接测试。

VSTO 加载项必须使用 Visual Studio 自带的 MSBuild 构建，不能使用 `dotnet build SmartWord.sln` 代替。

## 模型与隐私

SmartWord 不自带模型。完成任务所需的段落、选区或工具结果可能会发送到你配置的模型服务商；使用前请确认服务商的数据处理政策。连接测试只发送固定短文本，不读取当前文档。

- API Key 只保存在本机设置中，并使用 Windows DPAPI 保护；界面不会回显完整密钥。
- 对话、任务历史、任务进度、用户 Skill 和日志默认保存在当前 Windows 用户的 `%AppData%\\SmartWord` 下。
- 使用本地模型可以减少文档内容离开本机的范围，但仍应检查本地服务的访问控制。
- Skill 脚本在受控环境中运行，不能直接修改 Word；当前防护不是操作系统级强沙箱，也不会自动安装第三方依赖。

## 常见问题

### 它和普通 AI 聊天工具有什么区别？

普通聊天工具通常需要你手动复制内容、描述位置，再把建议复制回 Word。SmartWord 直接连接当前文档，能理解段落和结构，在 Word 中定位并执行修改，最后重新检查结果。

### 它和 Word 的查找替换有什么区别？

查找替换适合精确匹配；SmartWord 可以先理解上下文，再按“只改选区”“统一某类标题”“保留数字和事实”等自然语言规则处理，并把复杂任务拆成可确认的步骤。

### 它会不会一下子改完整篇文档？

不会默认这样做。选区任务优先处理选区，写入前也可以要求确认。对于影响范围较大的任务，建议先让 SmartWord 列计划或先做只读检查。

### 我的文档受保护或只读，还能用吗？

可以问答、总结和检查；写入会在开始前停止。需要修改时，请解除保护或另存为可编辑副本。

### 为什么模型连接成功，却不能读取文档？

文档问答需要模型支持 OpenAI 兼容的工具调用能力。请确认服务商、模型名称和接口地址正确，并在设置页重新测试连接。

### 数据保存在哪里？

默认位于 `%AppData%\\SmartWord`：设置为 `settings.json`，对话和任务历史为 `smartword.db`，任务进度在 `todo\\`，用户 Skill 在 `skills\\`，日志在 `logs\\`。删除前请先备份需要保留的内容。
