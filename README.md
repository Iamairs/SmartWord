# SmartWord

## 让 Word 真正听懂你的话

SmartWord 是 Microsoft Word 里的 AI 文档副驾。

你不需要先学习复杂的菜单、宏或脚本，只要告诉它想完成什么：

> “把这段话改得更正式。”
>
> “找出全文中所有术语不一致的地方。”
>
> “总结第三章，并列出仍需确认的风险。”
>
> “统一所有一级标题的格式，先让我确认再修改。”

SmartWord 会在当前文档中读取相关内容，给出带出处的回答，或在你的确认下完成修改。每次写入都会经过验证，任务也可以暂停、取消或撤销。

## 三步完成工作

1. **选中内容，或把光标放到目标位置**

   SmartWord 会优先理解你的选区和附近上下文；处理整篇文档时，也会先建立文档结构。

2. **用自然语言描述目标**

   你可以直接提问，也可以从“总结全文”“润色选区”“文档体检”“统一格式”等快捷任务开始。

3. **查看结果，再决定是否应用**

   只读任务会返回答案和文档出处。涉及修改的任务会展示影响范围、风险和操作摘要；确认后才会写入 Word，并在写入后检查结果。

## 你可以用它做什么

### 读懂文档

- 总结全文、章节或当前选区
- 解释复杂段落，提炼要点和行动项
- 搜索关键词、正则表达式、术语和风险线索
- 读取表格、批注、页眉页脚和标题结构
- 点击回答中的出处，跳回 Word 的对应段落

### 改好文字

- 润色、压缩、扩写或改成正式表达
- 检查错别字、病句、重复和术语不一致
- 将多处表达统一成指定风格
- 在确认后替换原文、插入段落或删除不需要的内容

### 整理文档

- 检查标题层级、段落格式和常见排版问题
- 处理批注和待办事项
- 按步骤执行批量整理，并保留任务进度
- 对复杂的表格、格式或跨章节任务生成计划后再执行

### 复用工作流

Skill 是可复用的工作流能力包。你可以启用内置 Skill，也可以创建自己的规则，例如“季度报告润色”“合同术语检查”或“交付前文档整理”。

当前内置 Skill 包括：

- `document-finalizer`：交付前检查和收尾
- `business-report-polish`：业务报告表达优化
- `term-consistency-check`：术语一致性检查

## 为什么修改过程更放心

SmartWord 把“能修改”设计成一个可审阅的过程，而不是一次黑箱操作：

- **先读后改**：先确认当前 Word 文档中的事实和范围。
- **改前可确认**：确认面板用自然语言说明要改哪里、改什么、风险如何；技术细节默认收起。
- **改后会验证**：写入完成后自动回读并检查结果，未验证的内容不会直接标记为成功。
- **出错可回退**：验证失败、任务取消或文档切换时，会优先回滚当前写入步骤。
- **过程看得见**：可查看任务进度、工具轨迹、已验证改动和任务历史。
- **范围有边界**：只读模式不会修改文档；只读、受保护或不可写文档不会被强行写入。

重要文档仍建议先另存一份副本。自动验证和撤销机制用于降低风险，不能替代人工审阅和正式版本管理。

## 三种工作方式

在输入区可以选择最适合当前任务的方式：

| 工作方式 | 适合做什么 | 是否修改文档 |
| --- | --- | --- |
| **对话交流** | 提问、总结、解释、查找和体检 | 不修改 |
| **规划任务** | 把复杂目标拆成可审阅的步骤 | 等你确认后执行 |
| **自主执行** | 按任务板完成多步修改并持续验证 | 按权限和确认设置执行 |

如果你只是想了解文档，从“对话交流”开始；如果任务会影响大量内容，先规划再执行通常更稳妥。

### 你来决定自动化程度

工作方式和权限是两件事：工作方式决定任务怎么推进，权限决定 SmartWord 是否需要在写入前等你确认。推荐新用户使用“写入前确认”。熟悉工作流后，可以选择“自动安全写入”；“全自动执行”只适合副本或低风险文档。

无论选择哪种权限，文档写入、复杂脚本和外部 Skill 脚本都受运行时检查约束。只读模式不会被模型请求自动升级，受保护或不可写的文档也不会被强行修改。

| 权限 | 你会看到什么 |
| --- | --- |
| 只读 | 只回答、检索和检查，不改文档 |
| 写入前确认 | 每次修改前显示范围和风险，由你决定是否执行 |
| 自动安全写入 | 常规整理可连续执行，脚本类操作仍会请求确认 |
| 全自动执行 | 尽量连续完成任务，请只在副本或低风险文档中使用 |

## 开始使用

从源码安装 SmartWord 后，它会作为加载项出现在 Word 功能区中。

### 运行环境

- Windows
- Microsoft Word 2016 或更高版本
- .NET Framework 4.7.2
- Visual Studio 2022 或 Build Tools，并安装 Office/SharePoint 开发工具
- Visual Studio Tools for Office Runtime（VSTO Runtime）
- 一个 OpenAI 兼容格式的模型服务（云端或本地）及 API Key

### 构建并打开

在仓库根目录运行：

```powershell
.\build.ps1 -Frontend
.\build.ps1 -AddIn
```

然后在 Visual Studio 中启动 `src/SmartWord.AddIn`，或使用构建产物部署加载项。打开 Word 后，在功能区点击 **SmartWord**，进入设置页填写模型服务地址、模型名称和 API Key，先点击“测试连接”。

项目的 VSTO 加载项必须使用 Visual Studio 自带的 MSBuild 构建；不要用 `dotnet build SmartWord.sln` 代替。

## 模型与隐私

SmartWord 不自带模型。你配置的服务商决定了哪些文档内容会离开本机：完成任务所需的段落、选区或工具结果可能被发送给该服务商。连接测试使用固定短文本，不读取当前文档。

- API Key 只在本地设置中保存，并使用 Windows DPAPI 保护；界面不会回显完整密钥。
- 对话、任务历史、任务进度和用户 Skill 默认保存在当前 Windows 用户的 `%AppData%\\SmartWord` 下。
- 日志和历史主要保存状态、摘要和必要的操作信息，并对常见密钥字段做脱敏；请不要把额外机密写入提示词或 Skill。
- 使用本地模型可以减少文档内容离开本机的范围，但仍请确认本地服务本身的访问控制。

## 扩展你的 SmartWord

你可以在 Skill 页面创建自己的工作流，也可以从本地文件夹、公开 GitHub 仓库或 HTTPS ZIP 导入第三方 Skill。导入前，SmartWord 会展示来源、包含的资源、脚本和风险信息。

外部 Skill 的脚本默认关闭，运行前需要你的单独授权。请在确认来源和用途后再启用第三方 Skill，不要运行来源不明的脚本。

## 常见问题

### SmartWord 会不会自动修改全文？

不会默认这样做。选区任务优先处理选区；写入是否自动执行由权限设置决定。推荐使用“写入前确认”，在确认面板查看影响范围后再应用。

### 我的文档是只读或受保护的，可以使用吗？

可以进行问答、总结和检查，但写入会在开始前被拦截。请解除保护或另存为可编辑副本后再执行修改。

### 为什么模型连接成功，却不能读取文档？

SmartWord 的文档问答需要模型支持 OpenAI 兼容的工具调用能力。请在设置中运行连接测试，并确认服务商、模型名称和接口地址正确；不支持工具调用的模型只能进行普通文本对话。

### Skill 脚本能直接改 Word 吗？

不能。Skill 脚本用于受控的数据处理，Word 修改仍需经过 SmartWord 的文档写入、权限确认、撤销和验证流程。

### 数据保存在哪里？

默认位于 `%AppData%\\SmartWord`：设置在 `settings.json`，对话和任务历史在 `smartword.db`，任务进度在 `todo\\`，用户 Skill 在 `skills\\`，日志在 `logs\\`。删除这些文件前请先备份需要保留的内容。
